Run the final command inside the canonical revealline-soundtracks checkout. If Node says it cannot find intake/add-music.mjs, you are in the wrong folder.

1. Prepare your computer once

Install Node.js 20+, ffmpeg/ffprobe, Git and GitHub CLI. Authenticate with gh auth login, then: 

git clone git@github.com:mekhovov/revealline-soundtracks.git
cd revealline-soundtracks
git switch main
git pull --ff-only

2. Choose an intake path

Browser first

  1. Open Add music.
  2. Choose MP3 files or a folder.
  3. Enter rights, styles and collections.
  4. Download the .rlintake package.
node intake/add-music.mjs \
  "/absolute/path/to/package.rlintake" \
  --open-pr

Direct command

Pass one MP3 or a recursive folder directly to the intake script. This is fastest when the metadata applies to the whole batch. 

node intake/add-music.mjs \
  "/absolute/path/to/music" \
  --source "https://creator.example/song" \
  --artist "Artist name" \
  --styles "metal,UA" \
  --collections "Artist name,Gameplay" \
  --license cc-by-4.0 \
  --confirm-rights \
  --open-pr

3. Folder example with multiple collections

This adds every MP3 below the folder and places each song in both TRENCH ORDERLY and ФПВ: 

node intake/add-music.mjs \
  "/Users/oleksandr.mekhovov/work/my_projects/go_test/docs/research/dah-soundtracks/TRENCH ORDERLY/" \
  --source "https://www.youtube.com/channel/UCK74qKH4LfMX7JIXIcX35qw" \
  --artist "TRENCH ORDERLY" \
  --description "Пісні про ФПВ" \
  --styles "ФПВ,UA" \
  --collections "TRENCH ORDERLY,ФПВ" \
  --license unknown \
  --confirm-rights \
  --open-pr

Use a plain quoted URL. Do not paste Markdown link syntax and do not escape https://.

4. Licence values

Value Use
cc0 CC0 1.0 Universal
cc-by-3.0 / cc-by-4.0 Creative Commons Attribution
cc-by-sa-3.0 / cc-by-sa-4.0 Creative Commons Attribution-ShareAlike; also provide --derivative-notice
unknown Uploader-confirmed permission. No open licence is claimed.

A source page alone is not permission. Use --rights-evidence when the actual permission evidence differs from --source.

5. What happens automatically

  1. Every MP3 is fully decoded and measured.
  2. Exact bytes, duration and SHA-256 are recorded.
  3. Artist, title, styles, collections and rights are generated.
  4. Hash-named audio assets are uploaded to a draft release.
  5. A codex/ branch is committed and pushed.
  6. The catalogue pull request is opened.
  7. After merge, Actions publishes the assets and deploys this site.

One intake accepts at most 20 MP3s and 64 MiB. Split larger folders into several PRs.

6. Review and verify

  1. Review artist, song names, styles, collections and rights.
  2. Wait for the PR verification workflow to pass.
  3. Merge the PR.
  4. Open the public player, filter the new collection and play more than one track.

The game reads the canonical catalogue dynamically. A newly merged batch does not require a per-song game code change.

Troubleshooting

Node cannot find the script

cd /absolute/path/to/revealline-soundtracks
git switch main
git pull --ff-only
node intake/add-music.mjs --help

The checkout is not clean

Commit or stash unrelated work before intake. The script refuses to mix generated publication files with unrelated edits.

ffprobe or gh is missing

ffprobe -version
gh auth status
Full details remain in UPLOAD_GUIDE.md. Exact audio is published as immutable SHA-256-named release assets.
